# NetBird 개념 정리

대시보드를 처음 보면 Peer, Network, Group, Policy가 뒤섞여 보인다.
이 문서는 그 관계를 정리한다. 우리 실제 구성을 예로 든다.

## 큰 그림

**"누가"와 "무엇에"를 나누고, 그 둘을 정책으로 잇는다.** 이것만 잡으면 나머지는 따라온다.

```
        [누가]              [정책]              [무엇에]

    User (사람)                              Network (묶음)
      └ Peer (기계)   ──── Policy ────→        ├ Resource (대상)
          └ Group (묶음)                       └ Routing Peer (관문)
```

---

## 왼쪽 — "누가"

### Peer — 망에 참여한 기계

컴퓨터 한 대가 peer 하나다. **클라이언트/서버 구분이 없다.** 전통적 VPN처럼
중앙 서버에 클라이언트가 붙는 구조가 아니라, 모두 대등한 참여자다.

```
swarm-manager     100.105.6.203     stg 서버
DESKTOP-J490TJ3   100.105.80.112    사무원 윈도우
```

### User — 사람

Keycloak 계정. 한 사람이 PC·노트북·휴대폰을 쓰면 **peer 3개가 user 1명에 묶인다.**
퇴사자는 Keycloak에서 계정만 비활성화하면 그 사람의 기기 전부가 차단된다.

### Group — peer들의 묶음

peer에 붙이는 꼬리표. **정책을 개별 기계가 아니라 그룹 단위로 쓰기 위해** 존재한다.

```
Routing Peers   swarm-manager
office-staff    사무원 PC들
```

사무원이 10명으로 늘어도 정책은 그대로다. 새 PC를 그룹에 넣기만 하면 된다.

---

## 오른쪽 — "무엇에"

### Network — 라우팅 단위 묶음

안에 두 가지가 들어간다.

| 구성요소 | 의미 | 우리 값 |
|---|---|---|
| Resource | 접근할 대상 | `10.10.2.0/24` |
| Routing Peer | 그 대상으로 가는 **관문** | `swarm-manager` |

### Resource — 접근 대상

세 가지 형태가 있다.

```
Single IP       10.10.2.233     한 대만
Entire Subnet   10.10.2.0/24    대역 전체    ← 우리가 고른 것
Domain          *.internal      도메인 기준
```

**등록한 만큼만 접근된다.** peer를 등록한다고 그 기계 주변 네트워크가 딸려오지 않는다.
반대로 `0.0.0.0/0` 같은 걸 등록하면 모든 트래픽이 터널을 타게 되므로 절대 하지 말 것.

### Routing Peer — 관문

**그 네트워크 안에 있으면서 다른 peer들의 트래픽을 대신 전달하는 기계.**

`10.10.2.233`(drive)에는 NetBird가 깔려 있지 않다. 그런데도 접속되는 것은
swarm-manager가 대신 전달해주기 때문이다. 덕분에 stg 서버 14대에 일일이 설치할 필요가 없다.

응답이 돌아오는 것은 **Masquerade** 덕분이다. swarm-manager가 출발지 주소를 자기 것(`10.10.2.9`)으로
바꿔서 보내므로, drive 노드 입장에서는 평범한 내부 접속으로 보인다. 그래서 stg 서버들은
NetBird에 대해 아무것도 몰라도 되고 설정을 하나도 바꾸지 않아도 된다.

---

## 가운데 — Policy (Access Control)

**"어느 그룹이 어느 대상에 접근 가능한가"**를 정한다. 포트까지 제한할 수 있다.

```
office-staff  →  stg-subnet  (TCP 38592만 허용)
```

이렇게 하면 사무원은 SFTP만 쓸 수 있고 다른 서버의 DB 포트에는 못 붙는다.

**정책이 없으면 통신이 안 된다.** peer로 등록됐다고 다 통하는 게 아니다.
이것은 결함이 아니라 의도된 기본 동작이다.

---

## Setup Key — 기계 등록용 코드

사람이 없는 기계(서버)를 등록할 때 쓰는 코드. 브라우저 로그인을 할 수 없기 때문이다.

Keycloak을 연동한 뒤로 **사람이 쓰는 PC에는 필요 없다.** 각자 계정으로 로그인하면 된다.
서버 등록에만 계속 쓴다.

---

## 라우팅은 어떻게 클라이언트까지 오는가

가장 헷갈리는 지점이다. 윈도우에 `10.10.2.0/24`를 입력한 적이 없는데 어떻게 그리로 가는가?

**관리서버가 내려보낸다.**

```
[대시보드]  10.10.2.0/24 리소스 생성 + 라우팅 peer 지정
                     ↓
[관리서버]  저장
                     ↓
[클라이언트]  접속하면서 받아옴
             "너 IP는 100.105.80.112"
             "10.10.2.0/24는 swarm-manager 통해서 가"
                     ↓
             받은 대로 OS 라우팅 테이블에 자동 기록
```

이후 앱이 `10.10.2.233`에 접속하면 OS 커널이 라우팅 테이블을 보고 NetBird 인터페이스로 보낸다.
**앱은 VPN의 존재를 모른다.** 평범한 TCP 연결을 열 뿐이다. 그래서 WebDrive든 WinSCP든
프로그램을 수정할 필요가 없다.

이것이 순수 WireGuard와의 결정적 차이다.

| | 순수 WireGuard | NetBird |
|---|---|---|
| 새 대역 추가 | 모든 클라이언트 설정 파일을 하나씩 수정 | 대시보드에서 한 번 |
| 직원 10명이면 | 10대 전부 손봐야 함 | 자동 반영 |
| peer 추가 | 양쪽에 공개키 수동 등록 | 자동 |

## 실전 — `netbird status` 읽는 법

```
Management: Connected      관리서버 연결
Signal: Connected          peer 연결 중개
Relays: 2/2 Available      중계 서버
Networks: 10.10.2.0/24     ★ 라우팅 수신 여부
Peers count: 1/1 Connected peer 연결 상태
```

### `Networks: -` 로 나오면

**정책 문제다.** 연결과 인증이 모두 정상이어도 이렇게 나올 수 있다.

NetBird는 라우팅을 아무에게나 주지 않는다. **정책상 그 네트워크에 접근할 권한이 있는
peer에게만** 내려보낸다. `-`는 "너는 이 네트워크를 쓸 자격이 없다"는 관리서버의 판단이다.

가장 흔한 원인은 **그 peer가 어느 그룹에도 속하지 않은 것**이다. 정책은 그룹 단위로
동작하므로, 그룹이 없으면 어떤 정책에도 걸리지 않는다.

```
해결: Peers → 해당 peer → Assigned Groups에 그룹 배정
      → Access Control에서 그 그룹을 정책 Source에 추가
```

### 접속이 타임아웃되면

| 증상 | 의미 |
|---|---|
| `WSAETIMEDOUT` / timeout | 패킷이 목적지에 **도달조차 못 함** → 라우팅 또는 정책 문제 |
| `Connection refused` | 도달했는데 그 포트가 닫혀 있음 → 서비스 쪽 문제 |

이 둘을 구분하면 어디를 봐야 할지 바로 갈린다.

## 우리 구성 전체도

```
DESKTOP-J490TJ3 ─┐
 (사무원 윈도우)   │
                 ├── Policy ──→  Network
swarm-manager  ──┘                ├ Resource: 10.10.2.0/24
 (Routing Peers)                  └ Routing Peer: swarm-manager
      │                                      │
      └────────── 관문 역할 ─────────────────┘
                                             ↓
                        10.10.2.233:38592  drive SFTP
                        10.10.2.75:8888    SeaweedFS
                        10.10.2.207        Keycloak
```

## 명명 규칙

환경 이름을 앞에 두면 dev·prod가 추가돼도 목록에서 바로 구분된다.
이름은 영문 소문자+하이픈(API·CLI에서 안전), 설명은 한글로 둔다.

| 대상 | 예 |
|---|---|
| Network | `biseo-stg` — 스테이지 환경 내부망 (Docker Swarm) |
| Resource | `stg-subnet` — stg 전체 대역, drive SFTP(38592)·Databasus 등 |
| Group (사람) | `office-staff` — 사무원 PC |
| Group (서버) | `Routing Peers` — 라우팅 관문 |
